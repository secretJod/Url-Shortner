## Confirmed bug: `/metrics` format vs. frontend `AdminPage.jsx` expectation

- **Backend** (`main.go:73-87`): `/metrics` gathers `prometheus.DefaultGatherer` and encodes with `expfmt.NewEncoder(..., expfmt.FmtText)` — this is the standard `# HELP ... # TYPE ... metric_name{labels} value` Prometheus text format, content-type `text/plain; version=0.0.4`.
- **Frontend** (`AdminPage.jsx:32-33`): `const res = await apiClient.get('/metrics'); setMetrics(res.data);` then reads `metrics.uptime_seconds`, `metrics.status_codes`, `metrics.avg_latency_ms`, `metrics.max_latency_ms`, `metrics.cache_hit_rate`, `metrics.cache_hits`, `metrics.cache_misses`, `metrics.events_processed`, `metrics.events_failed` — a **JSON shape**.
- Because the response `Content-Type` is `text/plain`, axios will **not** JSON-parse it; `res.data` will be the raw Prometheus text string. `metrics` state becomes a truthy string (so the "Failed to load" empty state never triggers), then `metrics.status_codes` is `undefined` on a string (`Object.entries(undefined || {})` → `[]`, harmless), but `metrics.avg_latency_ms?.toFixed(2)` and `metrics.cacheHitRate.toFixed(1)` (`cacheHitRate` is a plain `const`, not optional-chained) will either render `NaN`/`undefined ms` or throw, depending on exact field access — **the Admin page is functionally broken** and will never show real data.
- **Root cause, precisely**: there is a legacy JSON-producing type, `internal/metrics.Metrics` / `Metrics.Snapshot()` (`internal/metrics/metrics.go:63-93`), whose `Snapshot()` output shape **matches exactly** what `AdminPage.jsx` expects (`uptime_seconds`, `cache_hit_rate`, `events_processed`, etc. — field-for-field). This confirms the frontend was originally written against a JSON `/metrics` endpoint that has since been replaced by the Prometheus-format one in `main.go`, without updating the frontend or removing the now-dead `internal/metrics.Metrics` type. `middleware/metrics.go` still wires `MetricsMiddleware(appMetrics)` into every request (`main.go:63-65`), silently maintaining state that is now **never read by any HTTP handler** — confirmed dead code via `grep "Snapshot"` (zero call sites outside its own definition and the middleware that populates it).
- **Classification: BUG, Severity: MEDIUM** (broken admin UI feature, not a security or data-integrity issue, but a real regression a user will hit immediately on visiting `/admin`).

## Cross-cutting API issues

- **Inconsistent auth enforcement across "similar" endpoints**: `/api/links` requires auth, but `/api/stats/:shortCode` and `/api/links/:shortCode/clicks` — which arguably expose *more* sensitive per-visitor data (IP hashes, referrers) — require none. This looks like an oversight rather than a deliberate design (no comment in code justifies the asymmetry).
- **No pagination** anywhere except a bare `limit` query param (no cursor/offset, no `has_more`/total count in response) — acceptable at current scale, a scalability concern at higher volumes (see `07-scalability.md`).
- **No idempotency key support** on `POST /api/shorten` — retried anonymous requests (e.g. a mobile client on a flaky network) create duplicate links pointing at the same URL. Low severity today (no charge/side-effect beyond a row), but worth noting for API design maturity.
- **Error response shape is consistent** (`{"error": "..."}"`) across handlers — a genuine strength, evidenced by every handler reviewed above.
- **No API versioning** (`/api/...` not `/api/v1/...`) — fine for a pre-1.0 internal project, called out for production planning since breaking changes have no migration path today.

## PROPOSED PRODUCTION STATE — API changes

1. Require authentication + ownership check on `/api/stats/:shortCode` and `/api/links/:shortCode/clicks`, OR explicitly redesign them as intentionally-public with anonymized/aggregated-only output (no raw referrer/IP-hash exposure) — this is a decision for Phase 2 approval, not something to silently pick.
2. Add rate limiting to `GET /:shortCode` (the redirect route currently has none registered at all).
3. Fix or remove the Admin metrics page: either add a JSON `/api/admin/metrics` endpoint backed by the (already-implemented) `internal/metrics.Metrics.Snapshot()`, gated by real admin auth, or delete the dead JSON metrics code path and rebuild `AdminPage.jsx` against Prometheus's HTTP API / a Grafana embed instead.
4. Implement `DELETE /api/links/:shortCode` (owner-only) to back the existing (currently fake) frontend delete button.
5. Introduce `/api/v1` versioning prefix before any public/external API consumers exist, to avoid an un-versioned breaking-change trap later.
