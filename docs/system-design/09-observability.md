## PROPOSED PRODUCTION STATE

1. **Structured logging** using a standard library-compatible logger (e.g. `log/slog`, available in Go 1.21+ and thus already compatible with this project's Go 1.25 toolchain, zero new dependency, zero cost) emitting JSON with fields: `request_id`, `method`, `path`, `status`, `latency_ms`, `api_key_id` (if authenticated), `short_code` (where applicable), `error` (structured, not just a formatted string). Replace every `log.Printf`/silent-swallow comment identified above.
2. **Request ID middleware** (Fiber's built-in `requestid` middleware, already available transitively via the Fiber v2 dependency already in `go.mod` — no new dependency) propagated into the structured log fields and, where useful, returned in an `X-Request-ID` response header for client-side correlation during support requests.
3. **Fix or retire the legacy JSON metrics path** (`internal/metrics.Metrics`) per the `04-api-design.md` recommendation — either back a real `/api/admin/metrics` JSON endpoint with it (auth-gated, see `05-security.md` SEC-04) or delete it to stop computing dead state on every request.
4. **Alertmanager rules** for the free, self-hosted Prometheus/Grafana stack already in `docker-compose.yml` (no new infra cost): alert on redirect error rate > threshold, rate-limiter "fail open" events (once instrumented, see reliability doc), analytics worker `AnalyticsEventsFailed` rate > 0 sustained, and Postgres/Redis health-check failures once `/health` is fixed to check both.
5. **Provision Grafana dashboards as code** (a `provisioning/dashboards/*.json` + `provisioning/datasources/*.yml` checked into the repo and mounted into the Grafana container) so dashboards survive container recreation and are reviewable in code review — currently zero dashboards exist by default.
6. **Change Grafana's default admin password** via env var before any shared/deployed use (`docker-compose.yml:75-76` currently hardcodes `admin`/`admin`) — trivial fix, flagged here since it's an observability-stack config item.
